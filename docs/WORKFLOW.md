# 自动化编程流程（Workflow）— GregTech-Universe

> 本文定义 AI 在本仓库执行任务的**完整流水线**。
> 边界定义见 `AI-BOUNDARY.md`，命名/风格见 `CODE-STYLE.md`，任务拆解见 `tasks/`。
>
> **核心原则**：先判边界，再读代码，最后才写。每个阶段都有**准入门**与**准出门**，
> 门不过就停在原地报告，绝不硬闯。

---

## 流水线总览

```
S0 接收任务
   │
S1 边界预判 ──── 命中 🔴 → 停，出 diff 候审，不落盘
   │                        命中 🟡 → 出计划 + 精确 diff，等人工确认
   │                        全 🟢   ↓
S2 读取同类实现（先读后写）
   │
S3 输出任务卡（目标/模块/文件清单/验证方式）
   │
S4 分步实施（一次一步，最小 diff）
   │
S5 红线自检（逐条打勾，AI 自查）
   │
S6 编译与运行验证
   │
S7 报告（改了什么/为什么/验证结果/遗留风险）
```

---

## S0 — 接收任务

**动作**：解析用户需求，明确目标。
**准出门**：能用一句话说清「做完之后世界会变成什么样」。

不满足 → 回去问清楚，不猜。

---

## S1 — 边界预判（关键闸门）

**动作**：列出本任务**预计要碰的所有文件**，逐个对照 `AI-BOUNDARY.md` §1 打档。

输出边界表：

| 文件 | 档位 | 依据 |
|---|---|---|
| `src/main/core/.../Foo.java` | 🟢 | 允许：主源码目录 |
| `src/res/core/gtu_core.mixins.json` | 🟡 | 需确认：已有条目变更 |
| `gradle.properties` | 🟡 | 需确认：版本字段 |

### 分档处置

| 命中 | AI 必须做的事 |
|---|---|
| 🔴 | **立即停止实施**。说明触碰哪条红线 → 给不越界的替代方案 → 如确需越界，输出精确 diff 到终端，**不写磁盘** → 等人工确认 |
| 🟡 | 停止实施。输出**完整 diff 预览** + 变更理由 + 风险 → 等人工确认 → 确认后才执行 |
| 🟢 | 可继续 S2 |

**禁止**：先写了再说、把 🟡 当 🟢 蒙混、一次任务里夹带越界改动。

---

## S2 — 读取同类实现（先读后写）

**动作**：在 `src/main/<mod>/` 下找到**功能最接近的已有实现**，完整读一遍。

至少读：
1. 一个同类注册类（`init/BlockRegistries.java` 之类）
2. 一个同类业务类
3. 对应的资源文件（若有）

**目的**：新代码必须长得像现有代码，不是像 AI 想象的代码。

**准出门**：能指出「我要照抄哪个文件的哪种写法」。

---

## S3 — 输出任务卡

固定格式，**先输出，等确认，再动手**：

```
━━━ 任务卡 ━━━
ID：      GTU-<模块>-<序号>
目标：    <一句话，说清可验证的结果>
模块：    core | modpacks | physics
边界档位：🟢 全绿 / 🟡 含 N 项待确认 / 🔴 阻塞

文件清单：
  + src/main/<mod>/.../New.java        新增
  ~ src/main/<mod>/.../Existing.java   修改（改第 N 行的 XXX）
  + src/res/<mod>/assets/.../foo.json  新增

依赖变更：无
同步改动：注册类常量 → mixins.json → 模型/语言/配方（逐项列出）
验证方式：gradlew :<mod>:compileJava
          gradlew :<mod>:runData        （若动资源）
          gradlew :<mod>:runGameTestServer（若动行为）
风险：    <可能影响存档/性能/兼容的地方，或「无」>
━━━━━━━━━━━━━━━━
```

**准出门**：人工回复「可以」/「继续」/ 指出要改的地方。

> 批量任务（`tasks/` 里已拆好的多条）可以一次性确认，但每条仍需独立走 S4–S7。

---

## S4 — 分步实施

**规则**：
1. **一次一个 ID**，完成一个再开下一个，不并行铺开。
2. **最小 diff**：不顺手重构、不顺手重命名、不顺手格式化、不夹带无关修改。
3. 新增注册项时，按 `CODE-STYLE.md` §4 同步更新所有关联点：
   - 注册类常量（插到同类末尾，不追加到文件尾）
   - `src/res/<mod>/<modId>.mixins.json`（若是 mixin）
   - 模型 / 方块状态 / 语言 / 配方
   - 模块入口类的 `register(...)` 调用链
4. 注释解释「为什么」，不写「做了什么」。
5. 注释语言与相邻文件保持一致。

**准出门**：该 ID 的文件清单全部落盘，且无清单外文件被动过。

---

## S5 — 红线自检（AI 自查，不可跳过）

逐条核对，**在报告里逐条打勾**：

```
□ 未触碰 🔴 清单（src/generated / 二进制 / templates / 复合构建 / 存档）
□ 未触碰 🟡 清单，或已获人工确认
□ 所有注册走 DeferredRegister / GTRegistrate，无裸 Registry.register
□ 构造器与 static init 无重活，副作用已延后
□ 无空 catch、无 printStackTrace，错误日志带异常对象
□ 无硬编码 new ResourceLocation，全部走 id()/cid()/mid()
□ gtu_core 未引入 GTCEu / Create import
□ 已有注册 ID 未被删除或重命名
□ 无新增依赖；若有，build.gradle.kts 已同步且已在任务卡声明
□ 缩进 4 空格、无 tab、UTF-8、末尾换行
□ 无通配符 import、无未使用 import
□ 命名符合 PascalCase/camelCase/UPPER_SNAKE_CASE/snake_case
□ diff 只含本任务内容，无夹带
```

**任一条不通过** → 回到 S4 修，不要带着问题进 S6。

---

## S6 — 编译与运行验证

按任务卡声明的方式执行：

| 验证 | 命令 | 覆盖 |
|---|---|---|
| 编译 | `gradlew :<mod>:compileJava` | 语法/类型/API 正确性 |
| 数据 | `gradlew :<mod>:runData` | 模型/配方/语言生成 |
| 行为 | `gradlew :<mod>:runGameTestServer` | 逻辑正确性 |
| 客户端 | `gradlew :<mod>:runClient` | 渲染/模型/网络 |

**禁止**为了「让编译过」而：
- 删代码、注释逻辑
- 加 `@SuppressWarnings("unchecked")` 掩盖问题
- 把 `compileOnly` 改成 `implementation`（🟡 需确认）
- 改依赖版本号（🟡 需确认）

编译不过 → 报告具体错误，**不自行绕过**。

---

## S7 — 报告

固定格式：

```
━━━ 完成报告 ━━━
ID：        GTU-<模块>-<序号>
状态：      ✅ 通过 / ⚠️ 部分完成 / ❌ 阻塞

改动文件：
  + <path>   <一句话说明>
  ~ <path>   <改了哪里，为什么>

验证结果：
  gradlew :core:compileJava      ✅ 通过
  gradlew :modpacks:runData      ❌ <具体错误>

红线自检：12/12 通过（见 S5）

遗留风险：
  - <影响存档 / 性能 / 上游版本兼容的点>
  或「无」

需要人工做的下一步：
  - <需要人工测试的场景 / 需要确认的越界项 / 无>
━━━━━━━━━━━━━━━━
```

## 任务依赖与批量执行

`tasks/` 下的任务按 ID 编号，**存在依赖关系**：

```
GTU-core-001  ──┐
GTU-core-002  ──┼─→ GTU-core-010（依赖前三项完成）
GTU-physics-001 ─┘
```

规则：
1. **被依赖的任务未完成，不得开始依赖它的任务。**
2. 每个 ID 独立走完 S4–S7 再开下一个。
3. 单个 ID 阻塞（编译失败、需越界确认）→ **停下报告**，不跳过继续做后面的。
4. 同一模块的任务可连续执行；跨模块切换时重新走 S2。

## 与 AGENTS.md 的关系

| 文件 | 职责 |
|---|---|
| `AGENTS.md` | 最高约束 + 红线速记 + 工作流摘要（每次会话自动加载） |
| `docs/AI-BOUNDARY.md` | 边界的**判定依据**（路径表 + 逻辑红线详解） |
| `docs/CODE-STYLE.md` | 命名/结构/注册/资源规范 |
| `docs/WORKFLOW.md`（本文） | **自动化流水线**：阶段、闸门、自检清单 |
| `docs/tasks/*.md` | 具体任务需求列表（逐条标注边界档位与依赖） |

冲突时优先级：`AI-BOUNDARY.md` > `AGENTS.md` > `WORKFLOW.md` > `CODE-STYLE.md` > `tasks/*.md`。
