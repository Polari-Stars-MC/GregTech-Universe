## 四、questId 与章间依赖（跨章规则）

### questId 格式（F-06）

```
❌ 旧：1 + 章号(1位) + 模块序(2位) + 槽位(2位)     → 上限 9 章
✅ 新：    章号(2位) + 模块序(2位) + 槽位(2位)     → 上限 99 章

02-001 → 020001      03-001 → 030001      05-020 → 050120
```

> ✅ 推导：`05-020` = 章 `05` + 模块序 `01`（第 2 个模块，0 起）+ 槽位 `20`
> → `050120`。**之前写的 `052020` 是算错了**（误把模块序当槽位）。

⚠️ **实现约束**：FTB Quests 的 questId 字符集 / 长度未核实（工具缺失）。
按 [`DESIGN-chapter-framework.md`](DESIGN-chapter-framework.md) 的设计，
questId 由 `QuestId.of(QuestCoords)` **派生**，内容层零字面量 → 约束确定后只改 1 个类。

### 章间依赖（F-02）

```java
ChapterEntry.key("mechanical_era");   // 00
ChapterEntry.key("steam_age");        // 01
ChapterEntry.key("combustion_age");   // 02
ChapterEntry.key("lv");               // 03
ChapterEntry.key("mv");               // 04
ChapterEntry.key("hv");               // 05

ChapterEntry.prev("steam_age");       // → 自动解析到 01 章实际末条
```

> 不再用 `01-400` 这类硬编码数字 ID。
> **附带收益**：F-04 决定 ch04/05 并行实施，两条轨道改不到同一处 —— 锚点是并行安全的必要条件。
